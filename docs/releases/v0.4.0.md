# Release Notes

**Release:** v0.4.0  
**Milestone:** 4 – Observability and Operational Readiness  
**Release Date:** July 2026

---

# Overview

Version **v0.4.0** completes the observability milestone for the CloudOps Event Platform.

This release introduces production-oriented operational capabilities including structured logging, correlation identifier propagation, CloudWatch metrics, dashboards, alarms, Amazon SNS notifications, health checks, and standardized engineering documentation.

With this release, the platform evolves from a functioning distributed application into an operationally observable cloud-native system.

# New Features

## Structured Logging

Introduced structured logging throughout the application using consistent log templates and contextual properties.

Logged context now includes:

- EventId
- CorrelationId
- EventType
- Source

This improves log searchability and troubleshooting.

---

## Correlation ID Propagation

Every submitted event now receives a CorrelationId that is propagated across:

- API
- Amazon SQS
- Worker Service
- DynamoDB persistence
- Structured logs

This enables end-to-end tracing of individual events through the platform.

---

## CloudWatch Custom Metrics

The platform now publishes custom CloudWatch metrics under the namespace:

```
CloudOps/EventPlatform
```

Metrics include:

- EventsAccepted
- EventsProcessed
- DuplicateEvents
- EventsFailed

These metrics provide operational visibility beyond individual log entries.

---

## CloudWatch Dashboard

Added a CloudWatch Dashboard that provides a consolidated operational view of the platform.

Dashboard widgets display:

- Accepted events
- Processed events
- Duplicate events
- Failed events
- Alarm status

---

## CloudWatch Alarms

Added alarms for key operational conditions.

Current alarms include:

- DuplicateEvents
- EventsFailed

These alarms provide early notification of abnormal platform behavior.

---

## Amazon SNS Notifications

CloudWatch alarms now publish notifications to an Amazon SNS topic.

This establishes the foundation for future integrations with email, chat platforms, and incident management systems.

---

## Health Endpoint

Introduced:

```
GET /health
```

The endpoint provides a lightweight readiness check for deployment verification and operational monitoring.

# Known Limitations

The following enhancements are intentionally deferred:

- Distributed tracing (AWS X-Ray/OpenTelemetry)
- Dead Letter Queue
- Log retention policies
- Service Level Indicators (SLIs)
- Service Level Objectives (SLOs)
- CI/CD pipeline
- Docker containerization
- Automated deployment

These items are planned for future milestones.

---

# Upgrade Notes

After upgrading:

1. Deploy the updated AWS CDK infrastructure.
2. Start the API.
3. Start the Worker.
4. Verify the `/health` endpoint.
5. Execute the operational runbooks.
6. Confirm CloudWatch metrics are published.
7. Verify dashboard and alarms.
